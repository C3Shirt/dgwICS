# Factory I/O 与 CODESYS 四 agent 仿真系统

用户已于 2026-10-08 同意实现四个角色及补充的结构化接口、场景与控制反馈闭环。本文件记录实现范围。

## 数据与职责

1. Agent1 将自然语言转换为任务规格：对象功能、物流关系、控制流程、假设、协议、验收条件。
2. Agent2 从本机真实场景提取的部件模板中选型，输出场景计划。确定性文件生成器负责对象和标签 Key、位置、旋转、配置、驱动引用，保留原始输入文件。
3. Agent3 使用图片、对象清单、标签轨迹和 PLC 诊断检查场景及运行。反馈包含版本、证据、具体对象、问题类别、建议与置信度。
4. PLC Agent 根据任务和实际 I/O 合约输出声明、ST 实现与绑定要求。CODESYS 工具在基线工程副本上编译；部署与启动必须作为显式执行阶段记录结果。

普通编排器串行执行修改，限制修复次数，保存完整任务记录。模型通过 OpenAI-compatible HTTP 接口调用，可为四个角色分别选择模型。离线示例使用明确标注的固定响应来验证工具与状态机，不冒充真实模型或仿真。

## 第一版边界与验收

- 先支持现有 Factory I/O prefab 模板和 Modbus TCP，不宣称任意新三维模型或协议已验证。
- 场景文件解析通过、结构与引用验证通过、软件加载通过、PLC 编译通过、运行验收通过是独立状态。
- 标签以 Key 关联对象。地址、驱动槽位、传输编码、单位与缩放分开记录；未确认编码不得自动部署。
- 模型发现异常后分别路由到场景、PLC、通信工具或需求规划。未知原因不得直接修改 PLC。
- 每轮保存任务、场景、I/O、PLC 和配置的摘要。过期反馈拒绝应用。
- 运行验收依赖有时间戳的物料事件和实测数据；截图判断通过不能代替数值验收。
- 本机缺少模型配置或基线 PLC 工程时，报告具体缺失项并保留可执行命令和已生成产物。

## 检验顺序

先运行无模型的结构化工具测试和示例，再只读验证真实 Web API；随后使用配置的模型、场景加载工具与 CODESYS 工程做联机验证。未经实际执行的步骤在报告中标为未验证。
