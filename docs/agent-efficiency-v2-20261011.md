# 框架效率改进与新场景实验

本轮在现有 Python CLI 和原生适配层内改进调度、上下文、失败保护与恢复。
场景和 PLC 仍由外部模型生成，助手不手写实验布局或控制逻辑作为成功回退。

## 已落实的改动

| 问题 | 实现 | 留存证据 |
| --- | --- | --- |
| 唯一下一动作仍调用监督模型 | Supervisor 直接验证并记录确定性决定；只有需要选择或因果调查时调用模型 | `supervisor-routing.json`，规则决定不生成模型训练候选 |
| 角色收到完整历史和重复材料 | 监督视图保留状态/版本/失败/恢复范围；场景与运行视觉使用不同视图；PLC 源码只出现一份 | `context_projection`、输入原件哈希、候选精确请求和 `input_metrics` |
| 长轨迹占用上下文、数组索引误读 | 事件/故障优先采样；重复状态字典化；明确 GUID/名称/方向及全窗口原始首末值 | 原始 `evidence.json`、`signal_index`、`tag_status_patterns` |
| 在线内部状态在投影中消失 | 保留在线变量、验证状态、应用状态、错误、时间和源哈希 | `plc_diagnostics.result.online_probe`；未验证值不会升级为因果证据 |
| 失败持续烧模型调用 | 本次运行共享调用/已报告 token/时间/上下文预算；相同无效输出和合同错误重复则停止；A→B→A 修复周期检查 | `execution-budget.json`，检查点保留，失败分类 `execution_limit` |
| 交接失败后读到旧的通过反馈 | 按执行阶段选择最新交接取证和 `restart-feedback.json`；新交接不完整也不会回退旧反馈 | `resume.json.latest_runtime_review`、`investigation-source.json.runtime_stage` |
| 证据不足就重新写 PLC | 仅明确修复反馈使 PLC 失效；假设允许保留代码继续测量；恢复后仍重新执行联机验证 | 恢复计划的复用范围与失效原因 |
| 环境未就绪却已调用视觉 | Runtime 服务预检前置，并在部署前再次检查；权限失败返回工具处理 | `environment-preflight.json`，失败发生在模型调用前 |
| 工具只支持部分设备却反复要求模型调用 | 根据实测组件能力选择相对求解或绝对坐标模型路径，传递可用按钮列表 | `layout_solver_fallback`，缺少几何能力仍要求后续实测 |

默认每次尝试最多 24 次模型调用、600000 个服务报告 token、1800 秒、单次文本上下文
200000 字符。预算跨生成、审核和监督角色共享，新的恢复尝试单独记录预算。
token 限额在调用前用已经收到的用量检查，一次请求可能越过限额；服务不返回用量时
记录未知，不把它当作零消耗。图片不计入字符限额，但保留字节和实际服务用量。

静态产物通过内容和策略检查后复用；历史编译证明仅允许复用代码，不能复用旧部署、
Run 状态、连接或物理通过。新尝试仍加载、编译部署、连接、采样和视觉检查。
本轮没有实现长期在线会话池、任意工艺的离散控制编译器或完整局部 ST 修订系统。

## 本轮实验记录

`runs/observer-sc001-20261011-036`：复用原 SC001 模型产物，新的场景视觉一次通过；
随后 Runtime 已停止且服务启动权限被 Windows 拒绝，返回工具配置失败。没有 PLC 修复。
该失败促成服务检查前置；恢复服务的系统操作单独留存回执，不记为模型能力。

用户随后指定换新简单场景。新需求为一条 2 米输送带、单件供料、入口/出口检测、
末端移除、自动循环，无实体按钮、分拣或停留。

`runs/observer-simple-transfer-20261011-001`：由 CLI 从新需求调用模型。规划先引用了
不存在的按钮，布局工具又不支持所选皮带输送机的原生相对几何；两次相同布局失败
被预算保护停止。未生成可验收场景，也未进入 PLC 部署，不能算完成。

修复可用按钮上下文、规划过程与观测约束、布局能力选择后，通过 CLI `--resume`
进入 `runs/observer-simple-transfer-20261011-002`。规划策略改变意味着相关旧规划
重新校验，原始候选与失败轨迹保留。最终运行结果另行补充，不能预先声明成功。

所有模型候选继续是待审核数据，SFT/DPO 资格默认关闭。测试夹具、规则路由、系统
恢复操作、失败回放都不自动变成模型成功训练样本。
