# 视觉请求设计对照：2026-10-12

用户用简短问题向 qwen3.7-flash 提交三张图片，得到了传感器朝向等布局疑点。这足以说明此前不能把框架的空问题列表简单归因于模型无法提出视觉疑点。该回复同时有供料器/移除器识别错误、传感器类型猜测、屏幕左右推断输送方向等问题，不能直接当作正确验收或训练 gold。

## 与真实场景清单对照

归档场景：`runs/20261011-211847-d3f4b8e2/scene-003`。

- Emitter 是绿色供料器；截图另一端的橙色区域对应 Remover。不能把两者视为正在移动的红、绿箱子。
- 两个传感器的实际 prefab 都是 `DiffusePhotoelectricSensor`。没有依据删除它们并改换另一个传感器类型。
- 原生射线方向约为 `[0,0,1]`，与输送机的 Z 长轴同向。应核实有限射线与实际物料路径、物料尺寸和高度的关系；不能把所有工业场景的传感器约束成必须垂直安装。
- 世界 Y 是高度；Z 为水平轴。相机斜视造成的屏幕倾斜不能作为输送机布置错误的证据。

## 实际请求对照

通过命令行诊断脚本调用框架的 ModelClient、预算、公开日志和训练候选记录。真实使用的请求与返回模型均为 `qwen3.8-flash`，不是用户报告的 `qwen3.7-flash`。三张原始图像哈希、43,819 字符的归档 payload、模型、端点、请求选项均保留；不修改软件或原始输入。

| 条件 | 唯一改变 | 实际结果 |
| --- | --- | --- |
| 原始提示词约 10,027 字符 + 严格 JSON Schema | 对照基线 | pass，空 findings，格式检查通过 |
| 短布局提示词 435 字符 + 相同严格 JSON Schema | 系统提示词 | 服务回复是 JSON Schema 定义的数组，未形成场景审查结果 |

第三组把 `[0,0,1]` 错解为向上，并据此声称射线提高 Y。这与原生数据不符；其降低传感器、让移除器重叠输送带的建议未经验证，不执行。能够输出问题不等于问题正确，能够满足格式不等于场景正确。

本轮每个条件只调用一次，是诊断线索，不是模型准确率评测。严格 Schema 下的格式异常是实测结果；未据此断言供应商产品不支持此功能。它说明当前集成不能依赖该请求选项保证有效的审查回复。

## 请求设计应调整的方向

1. 布局阶段的输入突出当前场景目标、对象 ID/类型、预期连接与图片。只保留这一阶段必需的几何数据和测量缺口。完整 I/O、运行诊断和 PLC 数据按阶段提供。
2. 视觉模型先给出观察、疑点、图片证据和不确定项。问题字段应轻量；避免发现一个疑点就必须同时完成 PLC 因果诊断、版本复制和完整修复任务。
3. 程序根据实际发送的请求记录附加版本/关联信息；对象映射和原生测量核实模型的类型、坐标、方向和连接判断。对未证实的建议保持调查状态。
4. 经证据核实后才形成可路由的场景修复任务；运行审查使用独立目标与上下文。保留未执行几何检查不能放行的现有门槛。
5. 评测同时需要正常与异常场景，区分疑点召回、误报、物体识别、数值推理及格式成功率。用户的“当前场景存在什么问题”式提问可能诱导问题输出，不能只以生成问题数量衡量改进。

以上为证据支持的设计方向，尚未完成生产框架改造，也未修复当前软件中的场景或完成物理验收。短提示词候选文件位于 `artifacts/vision-prompt-ab-20261012-001/short-layout-prompt.md`。
